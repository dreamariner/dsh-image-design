# 005 · feat · 物理驱动的自由姿势系统

> 004 把素体做到 cm 级精确、把 8 个姿势的穿模问题查清修掉了，但姿势系统本身仍是
> **静态数值表**：每个姿势 48 个关节欧拉（16 关节 × 3 轴）手拧出来的，改一个数要在
> 8 个姿势之间反复试，还试不出「不穿模」的保证。004 的实测已经证明这条路走不通：
> 判据不可信时，照着调出来的角度必然也错。
>
> 本 issue 把姿势从**静态数值表**升级为**物理 + 约束求解的产物**：作者只声明意图
> （「手落在大腿上、腕离面 4cm」），规则（重力、接触、摩擦、关节限位、地面接触）
> 把它解成关节角；并给出自由调整的入口（视口抓肢体拖、面板目标控件）。

## 背景

### 用户原话（2026-11-18）

> 不能指望每个动作逐个来调，应该要有符合世界物理的规则来处理人体的动作摆放。
> 当前只是预设几个动作，最终实现是要能自由调整人物的动作。

> 再增加重力系统物理系统模拟真实世界？

### 为什么必须是「规则」而不是「再调一轮」

- 预设姿势的**数量**会随需求增长（站/坐/跪/躺/走/跑/跳/拿/推/指…），每加一个就手调
  48 个数，工程量线性增长且每次都要靠肉眼验收。
- 自由摆动作时，**没有人会先算好角度再填进去**；任何「拖到哪就摆哪」的需求都要求
  规则在运行时把意图变成合法姿态。
- 穿模、关节反折、悬空这类错误，规则可以**在运行时保证**，而数值表只能靠事后审计。

## 目标

1. **姿势由规则解出**：作者只给高层目标（末端位置/朝向），关节角由「物理 + 约束 + IK」
   迭代解出；预设姿势同样由规则生成，不再是手拧的 48 个数。
2. **运行时自动保证合理**：任何姿势（含手调的）都自动满足——不陷进躯干/腿、不反关节、
   不过伸、脚不离地/不穿地、手贴腿面是「压住」而不是「堆上去」。
3. **能自由调整**：视口里直接抓手臂/腿拖动；面板给出末端目标的数值控件。
4. **可复现**：相同输入必须解出相同姿态（定步长 + 固定子步上限），参考图归档仍逐字节可复现。

## 方案

### 三层架构

```
① 意图层  PoseTargets —— 作者声明的高层目标（不是关节角）
   每条末端（左手/右手/左脚/右脚）+ 头部 + 骨盆根：
     { side, part, goal: Vector3（躯干局部系）, forward?, pinned? }
   「手搭在大腿上」= 一个手部目标 + 物理自己把它压到腿面上

② 物理 + 约束层  solver.ts —— 定步长 PBD 子步循环
   每个末端是一个粒子（pos / vel / mass / goal），每子步：
     a. 外力：重力 + 连回 goal 的弹簧 + 阻尼
     b. 预测：pos += vel · dt
     c. 约束投影（位置修正）：
        · 地面接触（脚）：pos.y ≥ 地面
        · 身体接触（手/脚 vs 躯干/腿）：穿深沿接触法向推出 + 切向速度摩擦衰减
        · 关节限位：目标夹回可达域（肘屈 ≤150°、膝不可反折、踝 ≤60°/≥−50°、肩 ≤180°）
        · 自碰撞（手 vs 腿）同上
     d. 速度更新：v = (pos − posPrev) / dt
     e. IK：粒子的落定位置 → 肩肘腕 / 髋膝踝 角度（复用 ik.ts 的两骨解析解）
   收敛：固定 dt = 1/120、固定子步上限；位移小于阈值即「落定」→ 静止后零开销

③ 表现层  输出仍是 JointRotations（16 关节欧拉表）
   → viewer.setPose / ref.json 的 joints / 现有门禁测试，全部不用改
```

### 关键技术决策

| 决策 | 选择 | 理由 / 替代方案对比 |
|---|---|---|
| 物理作用在哪一层 | **末端目标层**（粒子 + IK 链） | 骨骼保持运动学链：肘的方向、腕的旋向由 IK 保证自然；真刚体引擎会让骨骼变成动力学 ragdoll，与 IK 意图对抗 |
| 物理引擎 | **不引入** rapier/cannon | 见下表 |
| 碰撞判据 | 复用 `contact.ts` 的**体段碰撞体** | 实测可靠（符号无歧义、不要求网格闭合）；网格带符号距离只用来量尺寸 |
| 关节限位 | 把**目标**夹回可达域（而非夹角度） | 夹角度会破坏链的末端位置；目标夹取后 IK 自然给出合法角度 |
| 确定性 | 定步长 + 固定子步上限 | 参考图归档要求逐字节可复现；不定步长的实时积分做不到 |

**为什么不引入真刚体引擎（rapier / cannon-es）**

| 维度 | 内置 PBD 软物理 | 真刚体引擎 |
|---|---|---|
| 骨骼 | 运动学 IK 链（肘向、腕旋自然） | 动力学 ragdoll，与意图对抗，链会塌 |
| 碰撞体 | 网格级（体段射线内外判定，接触位置准） | 胶囊级（手贴腿差 1~2cm，与 004 的判据口径不一致） |
| 依赖 | 无 | 插件多一个重依赖（bundle 体积、许可、加载） |
| 可复现 | 定步长即确定 | 需固定步数收敛才稳，跨机器有差异 |
| 工作量 | 求解器本体 + 接入 | 还要把 28 根骨映射成关节约束与马达 |

### 物理参数（初版，全部可调）

| 参数 | 值 | 说明 |
|---|---|---|
| `gravity` | 9.81 m/s² | 模型空间（y 向下为负） |
| 末端质量 | 手 0.5 kg / 脚 0.8 kg | 决定谁压得住谁（头部不是粒子，由头目标驱动脊柱朝向） |
| 弹簧刚度 `k` | 手 600 N/m / 脚 900 N/m | 连回作者意图的「肌肉」 |
| 阻尼比 `ζ` | 1.0（临界阻尼） | 过阻尼：不振荡，落定快 |
| 摩擦系数 `μ` | 0.25 | 接触时切向速度每子步衰减的比例（手放腿上不打滑） |
| `dt` | 1/120 s | 固定 |
| 单帧推进子步 | 8 | 每渲染帧推进的子步数（拖动时跟手） |
| 子步上限 | 240（2 秒模拟时间） | `settle()` 的上限；落定提前退出 |
| 落定阈值 | 0.01 m/s | 末速低于此即视为静止，之后零开销 |

> 参数实际取值见 `src/client/mannequin/solver.ts` 的 `DEFAULT_SOLVER_CONFIG`（单源，
> 上表是它的镜像；改参数只改那里）。

### 影响面

- **插件行为**：姿势从「查表」变成「求解」。旧归档里的 `joints` 仍可直接回放（`setPose` 保留），
  但若走 `targets` 求解会得到物理上更自然的姿态。
- **数据迁移**：不需要。`ref.json` 的 `joints` 字段保持不变语义；`targets` 是可选新增字段。
- **自守护栏**：
  - bundle 形态不变（仍是 host + client 双端）；
  - client 边界（`tests/client-boundary.spec.ts`）：新模块**不得** import `node:` 内建
    或 `@deepseek-ai/dsh-client-*`；
  - UI 组件沿用 dsh-ui-cell 复制件约定（类名 `css.xxx` 取、插件自有类 `idi-` 前缀、
    新样式在 `panel-css.ts` 的 `CELL_STYLES` 按依赖序插入）。
- **性能**：物理只在有变化时推进（拖拽 / 改预设 / 改体型），落定即停；单帧预算 <16ms。
